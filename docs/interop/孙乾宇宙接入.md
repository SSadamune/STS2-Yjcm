# 孙乾宇宙双向联动接入

对照仓库：<https://github.com/SSadamune/STS2-Sunqian-Universe/tree/feature/cross-mod-interop>。
2026-10-09 核对提交：`5c631501be161160b13c6c36fa9a26f381adcaaf`。
本轮只增加接口，不自动改变任何牌、角色、火攻/灼烧或剧本效果，不修改伙伴仓库。

## 孙乾宇宙 → 一将成名

复制 `examples/YjcmGameplayInterop.cs` 到伙伴工程；可自行改 namespace/class 名。
目标为 `Yjcm.Api.YjcmPublicApi, Yjcm`，不是 `Yjcm.Loader`。
依赖游戏与 RitsuLib，不引用 Yjcm DLL；在伙伴入口注册自己的程序集，并在框架延迟初始化完成后检查 `IsReady`。
所有 mutation 必须 `await` 在已有的原生同步战斗动作/Hook 内调用，沿用其 `PlayerChoiceContext`。
不能从按钮、后台线程或单个客户端直接调用，也不能 `.Wait()` / `.Result`。接口不替你生成联机动作。

### 火攻

- `IsHuoGongPower` / `GetHuoGongPower` / `GetHuoGongAmount` 查询、识别。
- `CreateHuoGongHoverTip` 创建原生悬浮说明。
- `ApplyHuoGong(context, target, amount, applier, cardSource, silent)` 返回实际施加的 `PowerModel?`。

```csharp
if (YjcmGameplayInterop.IsReady)
    await YjcmGameplayInterop.ApplyHuoGong(context, enemy, 3, Owner.Creature, this);
```

沿用 `PowerCmd.Apply<HuoGongPower>` 的人工制品、叠层和钩子，不直接插入 Powers。
火攻仅在其当前施加者弃牌时触发，不能漏传玩家的 `Creature`；每次按当前层数造成无视格挡伤害，再减少一层。
狂风翻倍/减层、铁索传导等既有逻辑不改。没有自动把孙乾“灼烧”换为“火攻”。

### 装备栏

固定编号：`0` 武器，`1` 防具，`2` 防御马，`3` 进攻马，`4` 宝物。
越界编号抛 `ArgumentOutOfRangeException`；不在战斗/没有装备栏时查询为空、修改返回 false。
**这里只操作玩家已经存在的装备栏，不自动把伙伴角色的普通充能球栏改成装备栏。**

| 接口 | 用途 |
| --- | --- |
| `HasEquipmentBar(player)` | 是否已有装备栏 |
| `GetEquipmentInSlot(player, slot)` | 当前球或 null，返回活实例，只读使用 |
| `IsEquipmentOrb(orb)` / `GetEquipmentSlotType(orb)` | 识别装备/返回编号；非装备返回 -1 |
| `IsEmptyEquipmentSlot(orb)` | 区分空槽与真正装备 |
| `IsEquipmentSlotAbolished(player, slot)` | 是否废除 |
| `CountAbolishedEquipmentSlots(player)` | 废除数量 |
| `GetAvailableEquipmentSlots(player)` | 存在且未废除的编号 |
| `GetEquipmentCatalog()` | 当前注册的真实装备球，独立可变副本；不含空槽/废除球 |
| `ChannelEquipment(context, player, orb, playSfx)` | 同类原位替换，不激发旧球；内部再克隆，不能共用活实例 |
| `ClearEquipmentSlot(context, player, slot)` | 移除装备并补空槽，不激发；不恢复废除槽 |
| `AbolishEquipmentSlot(context, player, slot)` | 废除已有槽，不激发 |
| `RestoreEquipmentSlot(context, player, slot)` | 恢复废除槽为空槽，不还回旧装备 |

修改返回是否实际完成；禁止重装废除栏位。宝物中的普通球也可查询/清空/废除/恢复。
装备替换沿用现有装备命令，更新原位视觉、战斗历史并等待 `AfterOrbChanneled` 钩子。
这些接口不允许外部凭编号塞入任意球，也不暴露 Yjcm 私有枚举/基类。

## 一将成名 → 孙乾宇宙

本模组已提供 `Yjcm.Interop.SunqianUniverseInterop` 可选代理：
目标 `Squ.Api.SunqianUniversePublicApi, sunqian-universe`；与该分支的项目程序集名对应。
覆盖灼烧施加/悬浮框、剧本施加/查询/移除/失效及次数、龙套演员识别、角色强绑定牌识别、稍作修改配置/请求。

```csharp
if (SunqianUniverseInterop.IsReady)
    await SunqianUniverseInterop.ApplyBurning(context, enemy, 3, Owner.Creature, this);
```

无伙伴时代理安全返回空/false/已完成任务，玩法必须在调用前检查 IsReady。
孙乾宇宙当前没有实现我们的 BCL JSON 回调协议，不自动向 `PublicApi.RegisterPartner` 冒充注册；双向玩法使用双方强类型可选代理。
已有 BCL 桥接 `Yjcm.Api.PublicApi` 仍保留，作为另一种元数据/回调扩展方式。

## 验证边界

双版本回归检查代理与实际 DLL 的签名、简单 fallback 和接口隔离；反向代理对照上述提交的公开签名。
还需双方在相同游戏与 RitsuLib 运行时版本下，实测加载顺序、火攻弃牌/击杀、装备更换/废除/恢复、双人联机与回放。
对方分支项目为 net10.0、RitsuLib 0.6.2；本项目维持既定双 API 快照，不为读取接口擅自升级游戏/框架。
未执行对方工程/脚本，也未把静态签名检查记为双方游戏内联动通过。
